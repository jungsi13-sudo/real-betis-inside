REAL BETIS INSIDE | Google Sheets 실제 신청 접수 연동

이미 생성한 운영관리 구글시트
https://docs.google.com/spreadsheets/d/12x05_fQgeSOutpf9NAnem8fEeqvS_yf9T5QxnxTbAX4/edit

완성 상태
- 구글시트 4개 탭(운영현황, 신청내역, 설정, 공개댓글) 생성 및 검증 완료
- 선수 1차 모집 목표 15명, 기존 신청 기준 11명, 목표까지 4명 (정원 제한 없음)
- 신청시 동시접수 LockService, 15명 이후 추가 신청 허용 및 중복접수 차단
- 신청 후 운영자 이메일 알림 및 결제선생 수동 청구 관리
- 웹사이트 상단/하단/고정바 공유 모집숫자 15초 간격 조회
- 운영자 승인 후 공개되는 댓글(같은 시트 사용)

사용자 본인 구글 계정에서 필요한 작업(5단계)
1. 위 구글시트 열기. '설정' 탭의 B4에 신청 알림을 받을 이메일 주소 입력
2. 구글시트 메뉴 '확장 프로그램 > Apps Script' 실행
3. 기존 Code.gs 내용을 지운 뒤 이 ZIP의 Code.gs 내용 전부 붙여넣고 저장
4. 상단 함수 목록에서 setupBetis 선택 → 실행 → 구글 계정 권한 승인
   이 함수를 실행하면 운영현황 시트의 기존 15명 상한 계산 수식도 자동 수정됩니다.
   메일 발송과 스프레드시트 접근 권한 요청은 정상입니다.
   '설정' B2=15, B3=11, B4=이메일주소가 유지되는지 확인하세요.
5. 우측 상단 '배포 > 새 배포 > 웹 앱' → 다음과 같이 설정
   실행 사용자: 나(본인)
   액세스 권한이 있는 사용자: 모든 사용자(Anyone)
   배포 후 https://script.google.com/macros/s/.../exec URL을 복사

사이트에 연결하기
- 이 ZIP의 script.js 맨 위 BETIS_CONFIG 중 appsScriptUrl: '' 을 찾고,
  '' 안에 위의 /exec URL을 붙여넣으세요.
- 수정한 script.js 포함 사이트 전체를 GitHub에 올리면 Vercel이 자동 배포합니다.
- ZIP 파일 자체를 GitHub에 올리는 대신 압축을 푼 파일을 저장소 루트에 올려야 합니다.
- 앱스 스크립트용 Code.gs 파일은 웹사이트 루트에 업로드하지 마세요.
  서버 측 스크립트 코드와 사이트 공개 파일은 분리하세요.

안전하게 기능 점검
1. 실제 배포한 사이트 열기: '미리보기 모드' 문구가 사라져야 합니다.
2. '운영현황' 탭 현재값 11/15, 1차 목표까지 4명 확인
3. 본인 휴대전화로 테스트 신청 1건 제출
4. '신청내역' 새 행과 운영자 이메일 알림 도착 확인
5. 사이트 상/하단 12/15명, 목표까지 3명 확인(다른 스마트폰에서도 확인)
6. 테스트 신청행 I열 상태를 '취소'로 변경 후 11/15로 되돌아오는지 확인
7. 공개댓글 테스트: 폼 댓글 작성 → 시트 '공개댓글' E열 상태 '검토 대기' 생성
   검토 후 '공개'로 변경하면 다른 방문자에게 표시됨.

운영 프로세스
- 신청 접수 (I열 '신청 접수') → 결제선생에서 69만원/59만원 청구서 발송
- 청구서 발송 후 K열 '발송', I열 '청구서 발송' 변경
- 결제 완료 확인 후 I열 '예약금 입금' 변경. 잔금 완납이면 '완납'
- 신청 철회/중복 등은 I열 '취소' 또는 '반려'로 변경해 카운트에서 제외
- 초기 11건은 설정 B3에만 있으며 세부 데이터는 별도로 보관해야 합니다.
- 15명은 1차 신청 목표이며 하드 정원이 아닙니다. 15명 넘어도 계속 접수되고 실제 신청 인원 그대로 보여줍니다.
- 기존 웹 앱 배포 후 Code.gs를 변경했다면 '배포 > 배포 관리 > 수정 > 새 버전 배포'가 필요합니다.
- 교체한 Code.gs에서 setupBetis를 1회 실행하면 '운영현황'!B5 수식이 =B3+B4로 자동 변경되어 15명 초과 신청도 그대로 집계됩니다.
- 학부모 동행 유형은 선수 1차 목표 15명 계산에 포함되지 않습니다.
- 카드번호·여권번호·주민등록번호는 신청 시트에 수집하지 않습니다.

중요
- 아직 앱스 스크립트 배포 권한 승인과 /exec URL 연결은 완료되지 않았습니다.
- 현재 소스 그대로 공개하면 신청 폼은 시연 모드이므로 실제 개인정보 수신이 되지 않습니다.
- 별도의 Work/Codex, Next.js, Supabase, 유료 DB가 필요하지 않습니다.
- 공개 스크립트 접수이므로 반복 악성 제출 방지 및 개인정보 접근권한 점검을 운영 중 실시하세요.
- 신청 접수는 결제 완료/최종 예약이 아닙니다. 실제 결제 확인 후 확정하세요.

추가 안내 · 기존 배포를 수정하는 경우
- Apps Script에 새 Code.gs를 붙여넣고 setupBetis를 실행하세요. 서버 코드도 15명 초과 차단을 해제합니다.
- 이미 /exec 웹 앱을 배포했다면 배포 > 배포 관리 > 수정 > 버전: 새 버전으로 배포하세요. 기존 URL을 유지할 수 있습니다.
- 구글 시트만 변경하면 웹사이트의 차단 로직이 남을 수 있으므로 반드시 script.js도 새 버전으로 GitHub/Vercel에 올리세요.
- 15명에 도달한 뒤에도 신청이 가능하며, 표시 문구는 '1차 목표 달성 · 추가 신청 접수 중'으로 바뀝니다.
